# Public catalog SQL performance
Legacy public endpoint read-only optimization: replace correlated lateral OR + ORDER BY LIMIT 1 for each catalog row with two pre-deduplicated sets by trimmed nonempty barcode and by variant. Exact barcode wins even when its commercial fields are NULL, and variant fallback is enabled only when no barcode winner. Both sets use updated_at DESC NULLS LAST, id DESC, matching old ranking. Same view, prices 13/16, company 3 variants, rows (including existing duplicates), stock filter and commercial rules. No new cache, index, migration, Bsale request, order change, or V2 flag. Logs include DB and mapping durations, count and stock mode, without customer or product data.

Isolated PG parity uses exact pre-change SQL, a synthetic 7,602-product catalog plus adversarial duplicate/NULL cases. Both price lists and stock flags, row multiset and established sort keys, actual public route and related contract tests. Timings are synthetic, not proof of production latency. Real catalog_view cost, connection/network and serialization must be observed after deploy. No production DB access. Roll back by reverting this PR if needed.
