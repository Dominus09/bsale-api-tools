# Configuración del sistema — OWNER (fase 1)

Menú ERP Administración → Configuración del sistema. API GET/PATCH /admin/system-features. Requiere ERP autenticado y OWNER real (AUTH_OWNER_USER_IDS), incluso para lectura. No confiar en claims UI ni localStorage. No expone tokens, contraseñas, variables arbitrarias ni endpoints de escritura de entorno.

Controles implementados: edición cajas/pallet, publicación de fotos, IA de fotos. Se conserva la autenticación, validación individual de SKU, firma de foto, SHA, auditorías y requisitos 070. La IA exige procesador y archivo u2netp instalado; no comprueba calidad de inferencia ni descarga modelos al activar. Los tokens/secretos y ENABLE_CATALOG_PHOTO_AI de build siguen en Coolify. No se expone selector público V2, PWA vendedores/bodega, auth, crons ni otros flags de infraestructura.

Migración aditiva 071 (aplicar en analytics real manualmente y tras backup). Tabla de overrides vacía: ambos esquemas ausentes o sin override => heredar valor ENV anterior. Si solo falta una tabla o hay error DB, deshabilitar funcionalidad; nunca reactivar silenciosamente. No caché entre workers. Un override explícito true/false tiene precedencia, incluso si la variable antigua sigue existiendo. NULL restaura valor ENV; después de migrar y validar, conservar overrides explícitos antes de retirar variables antiguas. Los controles pueden apagarse aunque falten requisitos; habilitar requiere prerrequisitos. Versiones optimistas, lock de fila, cambios y auditoría en una misma transacción. Sin invalidación de operaciones ya iniciadas, aplica a nuevas solicitudes. UI requiere actualizar/reabrir otros módulos para reflejar estado. No se crea ni modifica ninguna variable automáticamente.

Orden: aplicar SQL 071 verificado; desplegar API y ERP (test.quillotana.cl). Abrir panel como OWNER y activar cajas por pallet. Confirmar foto/IA y registrar un override explícito antes de eliminar variables ENV legadas. No retirar tokens, clave de confirmación ni flag de build. No deploy PWA o catálogo. Rollback de aplicación: versiones antiguas vuelven a leer env; restaurar env según último estado aprobado antes de revertir. No borrar tablas para hacer rollback.

QA: PG desechable, migración repetible, herencia, override true/false, persistencia entre conexiones, restaurar ENV, versión obsoleta, auditoría atómica, requisitos, fail closed, autorización no OWNER/PWA-only y contrato HTTP. No acceso a producción ni activación automática.
